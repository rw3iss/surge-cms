## Verified / no change needed
- Capacity returns on un-register: tier counts read `status IN ('valid','checked_in')` (`events.repo` `countSold*`), and the cancel sets tickets `cancelled` — places come back.
- Re-registering after un-register: `upsertRegistration` un-cancels the same row (ON CONFLICT → `status = 'registered'`).
- Entity reads are viewer-gated in SQL (`viewFloorCondition`) + `allows` for single reads; email audience reads as anonymous.
- `my-registration` / `unregister` are `user` tier; un-register is `events.registrations:cancel_own` via `EVENT_ROUTE_PERMISSIONS`.
- Card markup is deliberately per-surface (Solid / SSR article / email tables); shared rules already live in `@sitesurge/types` (`eventTierAvailabilityLabel`, `truncateEventText`, `normalizeEventsBlockSettings`).

## Lead follow-up (2026-10-21)
- **#10 — DONE.** `services/entities.ts` `list`: a type whose data provider has a per-viewer `allows` (today `event`) is never list-cached, whatever the Schema page caching says.
